# Complete codebase audit

Audit date: 22 November 2026 (IST). Baseline: ef01c7530bf78948e68094436128330b7f3e7912. Node.js 24.13.0 / npm 11.4.1. Audit and planning only; no product fixes, dependency changes, database mutations, or deployment.

## Method and limits

Reviewed application source, schemas, generated-client boundary, four database models, one migration and standalone SQL/seed definitions, configurations, three manifests/lockfiles, all test suites and project reports. [Inventory](evidence/source-inventory.json) hashes 126 relevant tracked files; generated/dependency/build artifacts are inspected through generation/build/runtime rather than treated as hand-maintained source. Requirements PDFs were freshly re-extracted read-only; their hashes are recorded. No dependency installer/remediation or product refactor was run. Existing running local servers were reused, not restarted or represented as a new production startup.

Evidence tiers: source inspection; deterministic mocked/unit test; explicit browser fixture; actual local HTTP; actual external weather/database; public deployment. These tiers are not interchangeable. The current read-only DB test is one test with multiple assertions; it conditionally tests VERIFIED records only when one exists (none exist). No write success or real database outage was induced. There are no five isolated write tests in this checkout to claim as skipped.

## Highest-risk confirmed defect

SFT-01 reproduction: load actual dashboard with valid persisted profile, wait for weather/advisory, install a browser-only clock and advance 65 minutes. Requests remained 4 before/after, advisory unchanged, stale-warning count 0. [Evidence](evidence/freshness.json). No response fixture or server clock change was used. Queries have no refresh interval, focus refetch is disabled, and WeatherPanel reads Date.now only during render. Existing tests cover already-stale fixture rendering, not aging in place. This requires a frontend freshness lifecycle fix and clock-driven regression tests, not changed engine thresholds.

## Boundaries of assurance

No public penetration test, complete secret-history forensic scan, smartphone/Firefox/Safari, measured performance/SLO, actual notification delivery, write isolation, disaster restore, tenant authorization or qualified medical/language review was performed. No unused-dependency removal or speculative dead-code cleanup is justified by this audit. Reserved codes, explicit mocks, seed examples and employer drafts are intentional demonstration scope, not covert live functionality.
